# Память проекта WEB-Constructor

## Назначение
Windows-приложение для визуального создания сайтов, редактирования кода и экспорта независимых HTML/CSS/JS-проектов.

## Требования
- Python backend; веб-интерфейс в собственном окне приложения.
- Запуск через launch.vbs без видимой консоли; зависимости подготавливаются автоматически.
- CSS и JavaScript разделены на понятные файлы.
- Расширение через модульную систему.
- ИИ читает правила и память перед изменениями.
- Несвязанные части программы не затрагиваются.
- Встроенный подробный FAQ с иллюстрациями.
- Готовые сайты не зависят от Python или конструктора.

## Архитектурные решения
- Собственная версионируемая модель проекта, независимая от DOM и стороннего редактора.
- Редактор отделён от модели и экспортёра.
- GrapesJS может быть адаптируемым движком, но не форматом хранения.
- Модули общаются через публичные контракты.
- Динамическое исполнение модулей требует модели безопасности.
- Данные проектов хранятся вне каталога приложения в пользовательском каталоге данных.
- Изменения JSON-файла проекта записываются атомарно.

## Текущее состояние
- Основа приложения: FastAPI, Uvicorn, pywebview, локальный API и модульный реестр.
- Запуск через launch.vbs; main.py создаёт .venv и устанавливает зависимости из requirements.txt при необходимости.
- Project Management: создание, список, открытие, изменение основных настроек и удаление проектов.
- Project Model schema v2: метаданные, настройки сайта, страницы, ресурсы и меню навигации.
- Управление страницами: создание, переименование, изменение slug, назначение главной, удаление и изменение порядка.
- У каждого проекта должна быть хотя бы одна страница и ровно одна главная; slug и UUID страниц уникальны.
- При удалении главной страницы первая оставшаяся страница автоматически становится главной.
- Навигация: несколько именованных меню с размещением и древовидными пунктами; внутренние ссылки используют UUID страниц, внешние — только HTTP/HTTPS.
- При удалении страницы связанные пункты меню и их вложенные поддеревья удаляются автоматически.
- Каждый проект хранится в отдельной папке с project.json, assets/ и exports/.
- Миграции последовательно переводят старые форматы в текущую схему и отклоняют неизвестные будущие версии.
- Визуальный редактор работает с деревом ContentNode по id узлов, а не с DOM. Холст и панель «Слои» только показывают это дерево. Секция добавляется в корень страницы; заголовок, текст и кнопка вкладываются в секцию. Перенос, вложение, порядок, дублирование и удаление строят новое дерево и вызывают запись снимка для Undo/Redo. Если выбранный id есть в снимке, выделение сохраняется. Инспектор меняет props выбранного узла. Сохранение идёт через ProjectStore API. Идентификаторы узлов уникальны внутри страницы; схема остаётся v2.
- Библиотека секций, расширенная типографика и Export Engine ещё не реализованы; меню сохраняются в модели, но не отображаются на экспортированном сайте.

## Обновление памяти
После архитектурно значимых изменений обновлять этот файл и связанные документы. Не записывать планы как реализованные функции.
