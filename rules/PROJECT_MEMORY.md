# Память проекта WEB-Constructor

## Назначение
Windows-приложение для визуального создания сайтов, редактирования кода и экспорта независимых HTML/CSS/JS-проектов.

## Требования
- Python backend; веб-интерфейс в собственном окне приложения.
- Запуск через launch.vbs без видимой консоли; зависимости подготавливаются автоматически.
- CSS и JavaScript разделены на понятные файлы.
- Расширение через модульную систему.
- ИИ читает правила и память перед изменениями.
- Несвязанные части программы не затрагиваются.
- Встроенный подробный FAQ с иллюстрациями.
- Готовые сайты не зависят от Python или конструктора.

## Архитектурные решения
- Собственная версионируемая модель проекта, независимая от DOM и стороннего редактора.
- Редактор отделён от модели и экспортёра.
- GrapesJS может быть адаптируемым движком, но не форматом хранения.
- Модули общаются через публичные контракты.
- Динамическое исполнение модулей требует модели безопасности.
- Данные проектов хранятся вне каталога приложения в пользовательском каталоге данных.
- Изменения JSON-файла проекта записываются атомарно.

## Текущее состояние
- Основа приложения: FastAPI, Uvicorn, pywebview, локальный API и модульный реестр.
- Запуск через launch.vbs; main.py создаёт .venv и устанавливает зависимости из requirements.txt при необходимости.
- Project Management: создание, список, открытие, изменение основных настроек и удаление проектов.
- Project Model schema v1: метаданные проекта, настройки сайта, страницы с editor-independent деревом nodes и список ресурсов.
- Каждый проект хранится в отдельной папке с project.json, assets/ и exports/.
- Миграционный механизм переводит начальный неверсированный формат в schema v1 и отклоняет неизвестные будущие версии.
- Визуальный редактор, управление содержимым страниц и экспорт ещё не реализованы.

## Обновление памяти
После архитектурно значимых изменений обновлять этот файл и связанные документы. Не записывать планы как реализованные функции.
