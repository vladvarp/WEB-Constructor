# Архитектура WEB-Constructor

## Слои
1. Application Shell — окно, навигация, общие панели и жизненный цикл.
2. Core — конфигурация, события, команды, хранение, версии данных и контракты.
3. Feature Modules — изолированные функции через реестр.
4. Project Model — независимое от UI представление сайта.
5. Editor Adapters — связь визуальных движков с Project Model.
6. Export Engine — генерация чистого сайта.
7. Documentation — FAQ и технические документы.

## Ограничения
- Project Model не зависит от GrapesJS или DOM.
- Export Engine не импортирует UI или pywebview.
- UI не меняет файлы проекта в обход сервисов хранения.
- Модули используют публичные интерфейсы Core.
- Формат проекта имеет schema_version и последовательные миграции.
- Экспорт содержит только используемые ресурсы и работает независимо от приложения.
- Идентификаторы проектов — UUID; они не используются как произвольные пути файловой системы.
- Запись project.json выполняется через временный файл и атомарную замену.

## Хранение проектов
- Windows: %LOCALAPPDATA%/WEB-Constructor/projects.
- Linux/macOS fallback: $XDG_DATA_HOME/WEB-Constructor/projects или ~/.local/share/WEB-Constructor/projects.
- Один проект — одна папка UUID.
- Внутри: project.json, assets/, exports/.
- project.json — единственный источник истины для метаданных сайта и дерева страниц.

## Project Model v2
- schema_version.
- project: id, name, created_at, updated_at.
- site: title, description, language.
- pages: id, title, slug, is_home, content.nodes.
- Каждый узел content.nodes имеет id, type, props и children; вложенность описывает структуру документа независимо от DOM. Идентификаторы узлов уникальны внутри одной страницы.
- assets: id, name, path, mime_type; пути ресурсов только относительные и без traversal-сегментов.
- menus: id, name, location, items; каждый пункт имеет UUID, label, kind, page_id/url и children.
- Внутренние ссылки используют UUID страницы; внешние ссылки — только абсолютные HTTP/HTTPS URL без credentials.
- Вложенность навигации ограничена пятью уровнями и 500 пунктами на проект; идентификаторы пунктов уникальны, page_id должен ссылаться на существующую страницу.
- У проекта хотя бы одна страница и ровно одна главная; slug и page id уникальны.

## API проектов, страниц и меню
- GET /api/projects — список.
- POST /api/projects — создание.
- GET /api/projects/{id} — открытие.
- PUT /api/projects/{id} — сохранение.
- DELETE /api/projects/{id} — удаление.
- POST /api/projects/{id}/pages — создание страницы.
- PUT /api/projects/{id}/pages/{page_id} — изменение названия и slug.
- POST /api/projects/{id}/pages/{page_id}/home — назначение главной.
- DELETE /api/projects/{id}/pages/{page_id} — удаление страницы; при удалении главной первая оставшаяся становится главной.
- PUT /api/projects/{id}/pages/reorder — изменение порядка страниц.
- POST /api/projects/{id}/menus — создание меню.
- PUT /api/projects/{id}/menus/{menu_id} — сохранение меню и дерева пунктов.
- DELETE /api/projects/{id}/menus/{menu_id} — удаление меню.

## Запуск
launch.vbs → pythonw.exe → main.py → проверка/создание .venv и зависимостей → FastAPI/Uvicorn → окно pywebview.
FastAPI слушает только 127.0.0.1; порт выбирается при запуске. Frontend и API обслуживаются одним backend.

## Модули
Текущий реестр только читает и проверяет modules/*/module.json. Динамическая загрузка — отдельный этап с разрешениями, зависимостями и изоляцией.

## Визуальный редактор
- Редактор работает с Project Model через отдельный frontend-адаптер. DOM холста только отображает дерево content.nodes и не является форматом хранения.
- Поддерживаемые узлы: section, eyebrow, heading, paragraph, button. Каждое действие выбора и структуры адресует узел по id.
- Секция вставляется в корень. Заголовок, текст и кнопка вставляются в секцию, найденную по id выбранного узла, его секции-предка или последней корневой секции.
- Перенос, изменение порядка, вложение, дублирование и удаление возвращают новое дерево ContentNode. Исходный массив узлов не изменяется на месте. Перенос внутрь собственного потомка не меняет дерево. Дублирование назначает новые id всему поддереву.
- История Undo/Redo хранит снимки дерева content.nodes. Если после шага выбранный id всё ещё есть в дереве, выделение сохраняется.
- Инспектор изменяет props выбранного узла. Документ сохраняется целиком через существующий API проекта.
- Предпросмотр поддерживает ширины Desktop, Tablet и Mobile; это визуальные режимы холста, не полноценная система адаптивных CSS-правил.
- Неподдерживаемые типы узлов показываются как безопасная заглушка, а не исполняются.
