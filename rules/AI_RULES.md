# Правила работы ИИ с WEB-Constructor

Обязательны перед каждым изменением.

## Проверка
- Прочитать этот файл, `PROJECT_MEMORY.md`, `ARCHITECTURE.md` и документы по задаче.
- Изучить реальные файлы и текущую ветку; не делать выводов только по README.
- Не заявлять о запуске или тестировании, если они фактически не выполнялись.

## Область изменений
- Менять только относящиеся к задаче файлы.
- Не переписывать соседние подсистемы ради удобства.
- Не менять публичные контракты без проверки потребителей.
- Не удалять функции без прямого требования.
- При изменении функции предоставлять её полную актуальную реализацию.

## Архитектура
- Соблюдать границы слоёв из ARCHITECTURE.md.
- Не обращаться к приватным внутренностям другого модуля.
- Формат проекта должен иметь версию и миграции.
- Экспорт сайта не зависит от runtime конструктора.

## Надёжность
- Добавлять тесты для изменённого поведения.
- Проверять ошибочные, пустые и повторные сценарии.
- Не скрывать исключения без логирования.
- Не хранить секреты и пользовательские временные файлы в Git.

## Зависимости
- Проверять поддержку, лицензию, размер и необходимость библиотеки.
- Фиксировать новые runtime-зависимости.
- Не исполнять сторонний код динамически без утверждённой модели безопасности.

## Git
- Каждую задачу выполнять в отдельной ветке от актуальной базы.
- Не изменять main напрямую.
- Коммиты описывают уже выполненную работу.
- В итогах перечислять фактически изменённое и реально проверенное.
