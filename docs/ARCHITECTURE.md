# Архитектура

Основные принципы находятся в [rules/ARCHITECTURE.md](../rules/ARCHITECTURE.md), история решений — в [rules/DECISIONS.md](../rules/DECISIONS.md).

## Хранение проекта

Проекты хранятся отдельно от каталога приложения, в пользовательской папке данных. Каждый проект имеет собственный UUID-каталог:

```text
projects/
└── <project-uuid>/
    ├── project.json
    ├── assets/
    └── exports/
```

Файл `project.json` содержит версионируемую модель сайта. Текущая схема — v1: метаданные проекта, настройки сайта, страницы и ресурсы. Дерево `content.nodes` состоит из узлов с `id`, `type`, `props` и `children`; оно не зависит от DOM или конкретного визуального редактора.

Изменения JSON записываются через временный файл с атомарной заменой. Миграции схемы находятся в `backend/projects/migrations.py`.

## API страниц

- `POST /api/projects/{id}/pages` — создать страницу.
- `PUT /api/projects/{id}/pages/{page_id}` — изменить название и slug.
- `POST /api/projects/{id}/pages/{page_id}/home` — назначить главной.
- `DELETE /api/projects/{id}/pages/{page_id}` — удалить страницу.
- `PUT /api/projects/{id}/pages/reorder` — сохранить порядок страниц.

В проекте всегда есть минимум одна страница и ровно одна главная. При удалении главной автоматически назначается первая оставшаяся страница. Slug и UUID страниц уникальны.

Содержимое страниц пока хранится в независимом дереве `content.nodes`, но его визуальное редактирование и экспортёр будут подключены отдельными этапами.
